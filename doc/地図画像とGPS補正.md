# 地図画像とGPS補正

## 目的

アプリ内で使用するキャンパスマップ画像に対して、GPS座標と画像ピクセル座標を対応付ける。

これにより、以下を実現する。

- 緯度経度から地図画像上のピン表示位置を算出する
- 地図画像上のピクセル位置から緯度経度を推定する
- バス停・建物・現在地などを画像上に正しく重ねて表示する

## 対象画像

使用する地図画像は以下。

```text
app/src/main/res/mipmap-hdpi/tatemono_no_number.png
```

画像サイズは以下。

```text
width  = 1632 px
height = 1904 px
```

画像座標系は以下を前提とする。

```text
左上 = (0, 0)
右方向 = x 正方向
下方向 = y 正方向
```

## 補正方法

画像ピクセル座標 `(x, y)` とGPS座標 `(lat, lon)` の対応には、アフィン変換を使用する。

単純な2点線形変換では、確認点で約8m程度のズレが出たため、複数点を使った最小二乗法によるアフィン変換を採用する。

変換式は以下。

```text
lat = a*x + b*y + c
lon = d*x + e*y + f
```

現在の8点から求めた係数は以下。

```text
lat = 3.10327166e-8 * x - 5.61667690e-6 * y + 35.47025654998892
lon = 6.87971687e-6 * x - 1.51774483e-8 * y + 136.7318515502264
```

## 実装方針

### 1. 座標変換用クラスを用意する

地図画像用の座標変換を1箇所に集約する。

例: `MapCoordinateTransformer` のようなクラスを作る。

責務は以下。

- pixel `(x, y)` から GPS `(lat, lon)` へ変換する
- GPS `(lat, lon)` から pixel `(x, y)` へ逆変換する
- 地図画像サイズを定数として保持する
- アフィン変換係数を定数として保持する

### 2. pixel から GPS への変換

以下の式を使う。

```text
lat = 3.10327166e-8 * x - 5.61667690e-6 * y + 35.47025654998892
lon = 6.87971687e-6 * x - 1.51774483e-8 * y + 136.7318515502264
```

### 3. GPS から pixel への逆変換

表示上はGPSから画像上のピクセルへ変換する処理が必要になる。

アフィン変換の線形部分を逆行列で解く。

元の式。

```text
lat - c = a*x + b*y
lon - f = d*x + e*y
```

係数。

```text
a = 3.10327166e-8
b = -5.61667690e-6
c = 35.47025654998892
d = 6.87971687e-6
e = -1.51774483e-8
f = 136.7318515502264
```

逆変換。

```text
det = a*e - b*d

x = ( e*(lat - c) - b*(lon - f)) / det
y = (-d*(lat - c) + a*(lon - f)) / det
```

### 4. 表示スケールを考慮する

地図画像をViewに表示する場合、画像の元ピクセル座標と画面上の表示座標は異なる。

そのため、以下を分離する。

```text
GPS座標 <-> 画像元ピクセル座標 <-> View上の描画座標
```

画像が `ImageView` や `Canvas` に fitCenter / centerCrop / 独自スケールで表示される場合、ピン座標には画像の表示矩形、スケール、オフセットを必ず反映する。

## Codexへの依頼内容

以下の方針で実装する。

```text
app/src/main/res/mipmap-hdpi/tatemono_no_number.png を地図画像として使用する。

地図画像の元サイズは width=1632, height=1904 とする。

画像ピクセル座標とGPS座標の変換には、以下のアフィン変換を使う。

lat = 3.10327166e-8 * x - 5.61667690e-6 * y + 35.47025654998892
lon = 6.87971687e-6 * x - 1.51774483e-8 * y + 136.7318515502264

GPSから画像ピクセル座標へ戻す逆変換も実装する。

逆変換では以下を使用する。

a = 3.10327166e-8
b = -5.61667690e-6
c = 35.47025654998892
d = 6.87971687e-6
e = -1.51774483e-8
f = 136.7318515502264

det = a*e - b*d

x = ( e*(lat - c) - b*(lon - f)) / det
y = (-d*(lat - c) + a*(lon - f)) / det

地図上にピンを描画する場合は、GPSから画像元ピクセル座標へ変換したあと、画像のView内表示矩形に合わせて画面座標へ変換する。

地図画像の表示方法によって、スケールとオフセットが変わるため、画像元ピクセル座標とView座標の変換処理を分離して実装する。

変換処理はMapCoordinateTransformerのような専用クラスに切り出し、ActivityやFragmentに直接係数を書かない。

バス停、建物、現在地などの地図上表示は、すべてこの変換クラスを経由する。
```

## 注意点

- 2点のみの線形変換ではなく、8点から求めたアフィン変換を使う
- 手作業で取得した基準点なので、1〜3m程度の誤差は許容する
- 画像を差し替える場合は、必ず再キャリブレーションする
- 画像サイズが変わった場合も、係数は再計算する
- `mipmap-hdpi` 内の画像を直接地図として使う設計で問題ないかは、Androidリソース運用として確認する
- 画像が密度スケーリングされるとピクセル座標系が崩れる可能性があるため、実装上は元画像サイズを基準に座標計算する
- 必要であれば `drawable-nodpi` に置くことも検討する
