## 12. KotlinからJavaへの移植方針

現在の実装がKotlin + Jetpack Composeで構成されている場合、Javaへ移植するにはUI方式の見直しが必要になる。

Jetpack ComposeはKotlin利用を前提とするため、Java移植では以下の方針を取る。

| 項目         | 方針                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| UI           | Jetpack ComposeからJava + XMLレイアウトへ移行する                                    |
| 画面遷移     | Navigation Composeではなく、Activity/Fragmentまたは単一Activity + Fragmentへ移行する |
| 状態管理     | Kotlin ViewModel実装をJava ViewModelへ移植する                                       |
| データクラス | Kotlin data classをJava classへ移植する                                              |
| enum         | Kotlin enum classをJava enumへ移植する                                               |
| ロジック     | 推薦エンジン、Dijkstra、CSVパーサ、祝日/学休日判定、移動時間補正をJavaへ移植する     |
| 永続化       | DataStoreはKotlin依存が強いため、JavaではSharedPreferencesまたは別方式へ置き換える   |
| 地図表示     | Compose CanvasからXML ViewまたはカスタムViewへ移植する                               |
| 優先順位     | まずlogic/model/dataをJava化し、その後UIをJava/XMLへ移行する                         |

移植は一括で行うと破綻しやすいため、以下の順序で進める。

1. modelパッケージのKotlin enum/data classをJavaへ移植する
2. logicパッケージの純粋ロジックをJavaへ移植する
3. dataパッケージのローカルデータ、CSVパーサ、祝日/学休日判定をJavaへ移植する
4. ViewModelと永続化処理をJavaへ移植する
5. Compose UIをJava + XMLレイアウトへ置き換える
6. 既存テストをJava実装に合わせて修正する
7. Kotlinファイルが不要になった段階で削除する

完全移植後は、プロジェクト内にKotlinソースが残らない状態を目標にする。
ただし、移植途中ではKotlinとJavaが混在してもよい。
